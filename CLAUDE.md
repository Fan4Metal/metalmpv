# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MetalMPV is a Windows-only video player written in Rust with egui/eframe 0.36 (glow); playback is libmpv's (`libmpv-2.dll`, loaded at run time). The layout is a classic player's: a frameless window with its own title row, the picture, a control bar under it (seek bar across the width; time on the left, the buttons in the middle with a round Play in their centre, volume and fullscreen on the right), an optional playlist on the right, a yellow OSD line in the top left corner after seeks. Priorities: opening a file fast, instant keyframe seeking, responsiveness, few settings. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone, no imperatives).

The name is written `MetalMPV` wherever people read it (UI, window title, READMEs, installer, `%APPDATA%\MetalMPV`, `%LOCALAPPDATA%\Programs\MetalMPV`, `MetalMPV_<ver>_Setup.exe`) and `metalmpv` wherever it is an identifier (Cargo package, `metalmpv.exe`, the GitHub repo `Fan4Metal/metalmpv`, the single-instance names).

## Commands

```
python tools/get_libmpv.py       # fetches the pinned libmpv-2.dll into vendor\libmpv (build.py and make_release.py do it)
uv run build.py                  # closes a metalmpv.exe running from target\, fetches libmpv if missing, cargo build --release
cargo build --release            # target\release\metalmpv.exe; build.rs copies libmpv-2.dll next to it
cargo test                       # unit tests (no DLL needed)
cargo test sys -- --ignored      # loads vendor\libmpv\libmpv-2.dll for real
cargo clippy --all-targets       # must stay warning-free
cargo fmt                        # default rustfmt (width 100)
python tools/make_release.py     # libmpv, tests, release build, dist\MetalMPV_<ver>_Setup.exe (Inno Setup 6) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy
python tools/icon_png.py         # images\icon.png from the exe's icon
python tools/notices.py          # licenses\THIRD_PARTY_NOTICES.txt after the dependencies change (a test fails until then)
METALMPV_TRACE=1                 # debug log with millisecond timings (start → window → file loaded → first frame), mpv's info messages
METALMPV_TRACE=2                 # also mpv's verbose messages
METALMPV_HWDEC=nvdec             # force mpv's hwdec option (measurements)
METALMPV_MPV="name=value;…"      # extra mpv options (measurements, diagnostics)
```

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files; the tag must equal the version in `Cargo.toml`. Creating or pushing a tag publishes a public release, so do it only when the user asks. `tools/setup.iss` installs per user. `.cargo/config.toml` links the CRT statically. These scripts mirror those of disk_flashlight, qview, qrec and metalmd; keep them in step (the libmpv steps are this project's own).

Trying a change: `cargo test` and `cargo clippy --all-targets`, then `uv run build.py` and run `target\release\metalmpv.exe <file>`; when the change concerns the installed copy (installer, portable mode, the DLL) or the user runs the program all day, `python tools/make_release.py --no-tests --install`. A test run with logs: start the exe with `METALMPV_TRACE=1` and stdout/stderr redirected to a file (the release exe has no console, but inherited handles work), close it with `taskkill /PID` (no `/F`).

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `metalmpv.exe` locks the release binary; `build.py` closes it first. Heredocs containing Rust code break the Bash tool (lifetime apostrophes), and backslashes in Python code passed through it get eaten; write files with the Write/Edit tools.

## Architecture

- **`main.rs`**: arguments (`--export-icon`, `--register`/`--unregister` (the file types, for the installer; named in the language of Windows), `--version`, `--help`, otherwise files; `normalize` fixes Explorer's `C:"`), `instance::forward` (a running copy takes the files), the panic hook, logging (`METALMPV_TRACE`), the **mpv start on a thread of its own** (`player::boot`: loading the DLL and `mpv_initialize`, ~15 ms) while eframe makes the window, `NativeOptions` (glow, `with_decorations(false)`, resizable, drag and drop, `window_builder` turning a saved fullscreen into maximized and a saved maximized into `MAXIMIZE_WHEN_SHOWN`).
- **`mpv/sys.rs`**: the libmpv C API declared by hand (client.h 2.5, render.h, render_gl.h): `LoadLibraryExW` of `libmpv-2.dll` next to the exe (a debug build also tries `vendor\libmpv`), `GetProcAddress` per function into `struct Api` (a macro), client API 2.3 or a later 2.x required (`API_MINOR`: mpv 0.38's `loadfile` with an index). The exe has no import of the DLL: without it the program starts and says what is missing (`sys::LoadError` into `player::EngineError`: `NoDll`, `BadDll`, `Failed`; `message()` is the window's text, wrapped under the icon, short for a missing or unusable DLL — the paths and Windows' error are the log's; the window title is the app's name while there is no engine). Struct layouts are tested (x64 sizes).
- **`mpv/mod.rs`**: the safe layer: `Mpv` (create with options, `command`/`set`/`get`/`observe`, all **asynchronous**, `next_event` with `mpv_wait_event(0)`, owned `Event`s) and `RenderContext`. render.h's threading rules: the render API is used on the UI thread, so the UI thread never calls anything that waits for the core; the synchronous `mpv_command`/`mpv_get_property`/`mpv_set_property` are deliberately not wrapped. The wakeup and update callbacks only call `ctx.request_repaint()`; since mpv may call them from inside a libmpv call, the app never calls mpv inside `ctx.input/memory/data` closures (egui's lock).
- **`player.rs`**: `Player`: mpv's options (`vo=libmpv`, `hwdec=auto-safe`, `keep-open=yes`, `video-timing-offset=0` so rendering never waits for a frame's display time, `audio-display=no`, mpv's own UI, bindings, scripts and config off), observed properties into `State`, `poll` → `Happened` (file loaded, end of file, failure, seek done, `Expanded`: a list mpv opened itself, an M3U at an address or inside a list, reported by `END_FILE` with `REDIRECT`; its entries from mpv's `playlist` replace the entry in the app's playlist (`Playlist::expand_current`) and `playlist-clear` leaves mpv only the one it plays); a `loading` flag from `load` to `FileLoaded`/failure ignores the end of the file before (Next in its last second skipped the file chosen); a `loadfile` refused (reply id `LOAD`) is a failure, an end of the file more than 15 s before the duration is `Happened::NoData` (`data_end`: the data ends early, a download not finished; within 3 s of a forward seek its target counts, as an MP4 then gives the duration as the position; otherwise the position, only in Matroska and MP4, whose durations are not estimates), and the app leaves mpv paused there (`stay_in_incomplete`), Play going on from where there was data (`data_end_at`), or moves on as at an end; commands with the seek mode always explicit (`relative+keyframes`, `relative+exact`, `absolute+…`, `frame-step`/`frame-back-step`).
- **`video.rs`**: the picture. The render context is made in `App::new` (eframe's GL context is current there) before the first `loadfile` (mpv's video output fails without it). mpv renders into an FBO with an RGBA8 texture of the video area's pixel size, inside an egui paint callback (`egui_glow::CallbackFn`), without `FLIP_Y` (mpv puts the top row first into an FBO, where egui expects it; the flag is for the default framebuffer); the texture is shown with `painter.image`. A size change re-specifies the storage of the same texture name (eframe cannot free a texture registered with `register_native_glow_texture`, a new one per size would leak). A new frame is rendered only when `mpv_render_context_update` says so or the size changed. While nothing is painted (minimised: eframe calls no `ui`; idle after Stop) `App::logic` calls `Video::skip_unseen` (`MPV_RENDER_PARAM_SKIP_RENDERING` and the swap report; eframe's GL context stays current on the UI thread), else mpv waited 200 ms per frame. `RenderContext` frees itself when dropped (an error path); replaced callbacks' boxes are kept. The swap is reported (`mpv_render_context_report_swap`) right after rendering: mpv makes no next frame before the report, and reporting it in the next paint took two paints a frame (240 fps video ran at 121 on a 239 Hz screen; at 60 Hz, 60 fps video could have run at 30). The callback runs for every frame a file is loaded, **before the video's size is known**: mpv publishes the size only after its first frame was rendered and otherwise waits 200 ms for it ("mpv_render_context_render() not being called or stuck"). `get_proc_address`: `wglGetProcAddress`, then opengl32.dll's exports.
- **`dock.rs`**, `App::playlist_window`: the playlist in a window of its own (`settings.playlist_detached`, `Cmd::TogglePlaylistWindow`: the playlist's last button, `icons::detach`, and the context menu). An immediate egui viewport as metalmd's detached tabs, frameless as the player's (`frameless::resize_edges`, its title row `ui::title::tool_row`: the name, close on the right, the rest drags it) (`show_viewport_immediate` in `ui`, the same `ui::playlist::panel` with `App` at hand; measured: a second immediate window does not lower the video's frame rate). The builder is made once per opening (a changed builder would move the window); eframe gives no handle, so the window is the visible one of the thread that is not the player's (`win::thread_windows`, again after `IsWindow` fails: the window may be made anew), put at `settings.playlist_rect` (its visible rectangle in pixels, DWM's extended frame bounds: `win::visible_rect`, `set_visible_rect`, kept each frame; else `dock::first_place`, the player's right edge) and adopted (`win::adopt_playlist`: owned by the player through `GWLP_HWNDPARENT`, so above it, minimised with it, no taskbar button; rounded corners; subclassed). Its `WM_MOVING` draws it to the player's edges (`dock::snapped`, the rectangle the pointer alone gives, as the player's own magnet); at `WM_EXITSIZEMOVE` it is glued to the edge it touches (`dock::glue_of`), and the player's `WM_WINDOWPOSCHANGED` puts a glued one beside it (`dock::placed`; not while minimised, maximized or in fullscreen: `set_playlist_follow`). Not shown in fullscreen while it overlaps the player. Keys work in it (Esc closes it), dropped files open as on the player (`App::drop_files`), media keys are hooked there too (`win::media_message`); its close button hides the playlist.
- **`playlist.rs`**: the playlist is the app's (one `loadfile … replace` at a time; `eof-reached` moves on): natural sort, folder contents (`MEDIA_EXTENSIONS`), M3U/M3U8 files (`PLAYLIST_EXTENSIONS`) replaced by their entries in `App::open`/`add` (`expand_lists`, `m3u_entries`: comments skipped, relative paths from the list's folder, addresses kept; a list does not fill the folder; an `#EXTINF` line describes the next entry as a `Channel`: the title after the first comma outside quotes, `tvg-logo`, `group-title`, control characters dropped; kept in `Playlist::channels` by path (`describe`, `channel`, `title`: the channel's name, else the file name; used by the list, the window title, Sort and saved frames) and written back by `m3u_text`). **`logos.rs`**: the channels' logos for the playlist's visible rows (`Logos::get`, `channel_logos`): only `https://` on port 443 and no local host or private IPv4 (`allowed`), WinHTTP (`win::https_get_once`: redirects followed by `fetch`, at most three, each checked by `allowed`; a host resolving to the local network, a trailing dot and odd numeric hosts refused), 512 KB, PNG/JPEG of at most 2048 px decoded with `image::Limits`, a 64 px texture; cached 30 days in `logos\<FNV-1a of the URL>` next to the settings (written as `.part` and renamed; a damaged copy fetched again; older ones deleted by a thread at the pool's start); at most `MAX_TEXTURES` kept, those shown longest ago dropped; four threads started with the first logo; `cargo test logo_of_a_site -- --ignored` goes to the network, current/selected entries that follow their files through removal and sorting; the playing entry removed stays the current path (`gone`) and the entry after its place comes next (`after_gone`); the entry playing chosen again starts over; entries are deduplicated with a set (lists of thousands).
- **`app.rs`**: the eframe `App`. Every action of keys, buttons and menus is an `input::Cmd`, gathered during the frame and run at its end (`App::run`). `logic` (also while minimised) takes other starts' files (`instance::take`; files arriving within 1.5 s make one playlist, as Explorer starts one process per selected file) and the player's events (end of file → next entry; a failed file is skipped). `ui`: dropped files, keys (focus surrendered first, nothing while a modal is open), resize strips, title row, control bar, playlist, the picture or a placeholder (the start screen as in qview — icon, name, version, hint — while idle, with the recent files under RECENT as in metalmd (`settings.recent`, `recent_files`, ten paths, the latest first, added on `FileLoaded` for files on disk while `remember_recent` is on; the whole page centred a little above the middle, each line centred under the hint; as many rows as the height allows, at most eight, the name and folder of each a clickable area over the video area's drag area; **Clear the list**; Forget in the settings clears them too, as does turning `remember_recent` off); an audio file's cover with its title, artist and album (`audio_cover`), else its title; the error), OSD (under the fullscreen title strip while that is shown), fullscreen panels (the control bar at the bottom and a strip with the file's name at the top that takes no clicks, `fullscreen_title`, both of `BAR_BG` with the `fullscreen_transparency`; each shown on its own while the pointer is near its edge, the bar also while a seek is dragged or the tracks window is open: `fullscreen_panels`; the pointer hides after 0.5 s of rest away from them unless the information window is open), Settings and About. The window is maximized while cloaked when it was saved maximized (`win::show_maximized`, qview's way). `on_exit` frees the render context before the core. The picture's context menu works as Windows' menus do (`video_area`): it opens when the right button pressed on the picture is let go and closes on any press off the menus, however far the pointer went meanwhile (egui's click allows 6 points, so clicks with the mouse on the move were lost); the middle button pressed on the picture shows or hides the playlist when let go, the same way (`middle_press`). `keep_awake` (in `logic`): mpv inhibits sleep only for its own video window, so the app calls `win::keep_awake` (`SetThreadExecutionState`, `ES_CONTINUOUS`) when it changes: display and system while a picture plays in sight, system for sound or a minimised window, nothing when paused, at the end or idle.
- **`frameless.rs`**: the window has no Windows frame but is resizable for Windows (`WS_SIZEBOX`/`WS_MAXIMIZEBOX`: Aero Snap, Win+arrows, maximizing to the work area, which winit's `WM_NCCALCSIZE` limits to `rcWork`). No window region (qrec's way loses the DWM shadow): `win::round_corners` asks DWM for rounded corners (Windows 11; square on Windows 10). Strips along the edges start `ViewportCommand::BeginResize`. The title row, the picture and the control bar's free space move the window (`frameless::drag_area`, `StartDrag`; not in fullscreen); those areas leave the 5-point edge strips alone, since a widget registered later covers an earlier one. Fullscreen turns winit's undecorated shadow off (`WindowExtWindows::set_undecorated_shadow`, the only use of the `winit` dependency), else winit moves the client area a pixel down and the bottom row falls off the screen. A window maximized before fullscreen stays `WS_MAXIMIZE` there and winit's `WM_NCCALCSIZE` gives it the work area (a black strip as tall as the taskbar, now and then): while `win::set_fullscreen` is on, the subclass answers `WM_NCCALCSIZE` itself with the window's rectangle within its monitor (`fullscreen_client`). The pointer is hidden with `CursorIcon::None` (egui-winit shows it again on any icon change after `CursorVisible(false)`).
- **`instance.rs`**: one window per exe (qview's): a mutex `Local\metalmpv.<hash of the exe path>` and a message-only window that takes all of a start's paths in one `WM_COPYDATA` (NUL-separated); the files of the start itself count as the first of a batch (`App::last_received`); `ChangeWindowMessageFilterEx` lets an elevated copy take them.
- **`input.rs`**: `Cmd`, and `keys`/`command` (each event's `keymap::Chord::of_event` looked up in the settings' `Keymap`, exactly: modifiers not in a chord must not be held; tested). The default keys: Space, Left/Right (short step on keyframes; the mouse's back and forward buttons, egui's `Extra1`/`Extra2`, are bound like them, with Ctrl and Shift as the arrows), Ctrl (long step), Shift (1 s exact), `,`/`.` and `D`/`F` (frames), Up/Down and the wheel (volume), `M`, Home/End, PgUp/PgDn, Enter/Alt+Enter/F11/double click (fullscreen), middle click on the picture (playlist, like `L`), Esc (`Cmd::Escape`: the information window, else the panel, else fullscreen, else the interface after `7`, else the program closes), Ctrl+O, `L`, F1, F5 / Ctrl+`,`, Delete, `I` (file information), `U` and `F7` (`Cmd::ToggleVideoPanel`: the Video, sound and subtitles panel; `U` next to `I`, `F7` as in GOM Player), `O` (the position, the duration and the chapter on the OSD, `Osd::Position`, as mpv's `o`), `1`–`4` (`Cmd::WindowScale`: the window for 50 %/100 %/150 %/200 % of the video), `5` (`Cmd::FitScreen`: the largest window without black bars), `` ` ``/`Ё` (`Cmd::FitWindow`: the window to the picture shown), `Ctrl+G` (`Cmd::GoToTime`, `ui/goto.rs`: a modal as the address's, the position in the field selected; `format::parse_time` takes `H:MM:SS`, `M:SS`, seconds, a fraction after `.` or `,`, `50%`, `+30`/`-1:00`/`+10%` from the position, clamped to the file; the time it names shown under the field; an exact seek), `Ctrl+U` (`Cmd::OpenUrl`, `ui/url.rs`: a modal with a field; `playlist::is_url` — a scheme before `://` — keeps an address out of `normalize`'s `absolute`, the cover search, Show in folder and the info's Folder row, which becomes Address; `ytdl=no`, so only direct links and streams), `Shift+.`/`Shift+,`/`Shift+0` (`Cmd::SubDelay`, mpv's `sub-delay` by 100 ms; egui has no `<`/`>` keys and passes the physical ones with Shift), `[`/`]`/`\` (`Cmd::LoopA`/`LoopB`/`LoopClear`, and `Cmd::CycleLoop` without a key: the A-B repeat, mpv's `ab-loop-a`/`ab-loop-b` through `Player::set_loop` (kept in order, observed as nodes into `State::loop_a`/`loop_b`, cleared by `Player::load`: mpv keeps them for the next file); `App::ab_loop`: an end without a start starts at 0, a start after the end drops the end, at least `MIN_LOOP`; yellow ticks and the stretch on the seek bar (`style::LOOP`), `Osd::Loop` to a tenth (`format::clock_tenths_in`), the context menu's **A-B repeat** submenu; the labels `Х`/`Ъ` in Russian; `cargo test ab_loop -- --ignored` plays a loop headless), `C`/`X`/`Z` (`Cmd::Speed`: the steps of `format::SPEEDS`, 0.25× to 4×, as in GOM; also the context menu's **Speed** submenu, `Cmd::SetSpeed`; mpv's `speed` with its pitch correction, kept between files, not saved), `6` (`Cmd::ToggleFill`: fullscreen with mpv's `panscan` 1, the picture cropped to fill the screen; `6` again puts `panscan` back to 0 and stays in fullscreen, leaving fullscreen does so too), `7` (`Cmd::ToggleInterface`: `Interface::Bare`, only the picture, no title row, control bar or playlist, and back to `App::before_bare`, the last other one shown (Full after a start in Bare); the context menu's first item **Show the interface** while hidden), `8` (`Cmd::CycleInterface`, `settings::Interface`: Full, NoTitle, Compact, Bare in turn, `Osd::Interface`; `Cmd::SetInterface` from the context menu's **Interface** submenu after Fullscreen; the OSD goes under it); with only the picture in a window the control bar of `settings.interface` comes over the bottom likewise (`App::wants_bar_over`: also while a seek is dragged or a window of the bar is open), in the picture's layer too, so the edges' strips stay; Compact is `controls::compact`, one row, Play left, the seek bar taking what is left, the optional buttons left out in turn below `MIN_SEEK`, also in fullscreen; the bar's panel has `controls::height` exactly. `App::fit_interface` (each frame, after the commands too): when the interface shown is not `sized_for`, the window grows or shrinks by the difference of `App::insets` (the title row, the bar, the docked playlist's width `playlist_inset`, measured), the picture staying put, kept on the work area; maximized, minimised or in fullscreen it waits for the restored window; `size_window` sets `sized_for`), all also in the context menu's **Zoom** submenu. Held keys repeat only seeks, frame steps, the volume and the delays (`Action::repeats`).
- **`keymap.rs`**: the keys the user can change. `Chord` (Ctrl/Alt/Shift and a `Press`: an egui `Key` or the mouse's back/forward button; `of_event` also turns egui-winit's `Copy`/`Cut` into Ctrl+C/Ctrl+X, which come without a key event; Ctrl+V is a paste and cannot be bound; modifier keys alone, which egui-winit passes as physical keys, are no chord), stored by `name` (`Ctrl+Shift+Left`, egui's `Key::name`, `MouseBack`) and shown by `label` (arrows, `Пробел`, `Ё`). `Action` (one macro line each: the id kept in the settings, the `Group` of the Keys page, the `Cmd`, the default chords; `name` in both languages; also a few without a default key: Stop, A-B repeat in turn, Load subtitles, Equalizer, Playlist window, Minimize, Maximize). `Keymap`: the chords per action; `assign` takes a chord from the action that had it; the setting keeps only the actions that differ from their defaults (`to_setting`/`from_setting`, an action not named keeps its defaults less the chords named ones took). `publish` copies the map into a static for `shortcut(cmd)`/`with_key(text, cmd)`: the labels of the context menu, its submenus' notes, the tooltips of the control bar, title row, playlist and tracks button, the start screen's hint; `App::new` and a `Changed::keys` publish it. The Keys page of the settings (`SettingsDialog::keys_page`, `capture_key`, as qrec's hotkey capture): rows per group with the keys as chips (a click waits for a press — key or side button — in its place, `+` for one more, the cross removes it; Esc or another click gives up, `gave_up` keeps that click from starting it again; the key events are taken out of egui's input meanwhile, so Esc does not close the modal), the action that lost a key named under the first card, **Reset the keys**; the window's Reset resets them too. The wheel, the double and middle clicks, media keys and the thumbnail buttons stay fixed.
- **`tracks.rs`**: the file's tracks from mpv's `track-list` (observed as `MPV_FORMAT_NODE`; `mpv/mod.rs` copies nodes into `Value::List`/`Value::Map`), their names in both languages (`name_in`: the language first, the title after a dash unless it names the language itself) and badges (`badges_in`: codec, channels, external/forced/default), cycling (`A` round the audio tracks, `S` and `J` through the subtitles and then none; Stop has no key, `V` off and back), `SUBTITLE_EXTENSIONS` (a subtitle file dropped on a playing video is added with `sub-add … select` instead of replacing the playlist). `cargo test track_list -- --ignored` plays a sample headless (`vo=null`, `ao=null`) and reads its tracks.
- **`resume.rs`**: where files were left and which tracks they played (`Positions`, `Left`, `Tracks`, tested): the position kept for files of 5 min or more between 10 s after the start and 30 s before the end; the audio and subtitle ids (`remember_tracks`) whatever the position, for files with more than one audio track or with subtitles; 200 at most, paths without regard to case. The app remembers the file playing before another is loaded, on Stop and in `save` (every 30 s and on exit), from mpv's `path`/`time-pos`/`duration`; `Player::load(path, start, tracks)` resumes with `loadfile … replace -1 start=…,aid=…,sid=…` (a file-local option; the index before the options since mpv 0.38) and the OSD says so. A file without tracks of its own to come back to gets, once loaded (`App::pick_like_tracks`, `prefer_last_tracks`), the audio and subtitles most like those last chosen by hand (`App::select_track` records them): `tracks::most_like` scores the same title 2 and the same language 1 (codes compared by their English names), nothing alike leaves mpv's choice; meant for series. mpv's watch-later files are not used: they bring back the volume too, and must be written by a command before every change of file.
- **`chapters.rs`**: the file's chapters from mpv's `chapter-list` (observed as a node, sorted by start; a title that only numbers the chapter, "Chapter 01", is dropped and the interface numbers it), `current` (the last started, 50 ms of slack). Shown as gaps in the seek bar (`chapter_marks`, toggled in the context menu's **Chapters** submenu and in the settings), the chapter's name in the seek bar's tooltip, a folding section under the playlist (its open state in egui memory) and the submenu; `Cmd::Chapter` seeks exactly (a keyframe seek lands in the chapter before) and shows the OSD's chapter line. `cargo test chapter_list -- --ignored` with METALMPV_SAMPLE reads a file's chapters headless.
- **`fonts.rs`**: the system's font families for the subtitle and OSD settings (fontdb, listed on a thread of its own the first time the settings page or the panel (which lays its Subtitles tab out even unseen) asks, never at start-up; each family's face nearest to an upright regular), `read` (a face for egui, checked with skrifa first: egui panics on a font it cannot parse). The subtitles take a family by name (`sub-font`, mpv/libass finds it; `sub-scale` for the size of all subtitles); the OSD is egui's, so its family's file and face number are kept in the settings and read at start-up (`style::set_fonts`, the family `style::osd_family`, backed by the interface's fonts).

## libmpv

`tools/get_libmpv.py` (stdlib only) downloads the pinned `mpv-dev-x86_64-20261012-git-88eb9f2e73.7z` of shinchiro/mpv-winbuild-cmake and 7-Zip's `7zr.exe` 26.03 (py7zr and Windows' tar cannot unpack the archive's BCJ2 filter), both checked by SHA-256, into `vendor\` (git-ignored, cached in CI by the script's hash). shinchiro keeps only the last 30 builds (about two months), so the archive is mirrored unchanged in a pre-release of this repository, `libmpv-<date>` (not a `v*` tag: no release workflow, not "latest"), tried first, the original as the fallback. Updating libmpv: mirror the new archive (`gh release create libmpv-<date> --prerelease --target main --notes-file … <archive>`, its hash checked first), change the constants there (asset name, both URLs, SHA-256 from the GitHub API's `digest`, the build's commit of mpv-winbuild-cmake — the tag's — and the FFmpeg commit the DLL names in `N-…-g<hash>`) and the same in `THIRD_PARTY_LICENSES.md` (the GPL's corresponding source). The DLL is ~115 MB unpacked. **The build is GPLv3** (mpv's `gpl` feature, FFmpeg `--enable-gpl --enable-version3`): the installer and the zip ship `THIRD_PARTY_LICENSES.md` with the source links, `licenses\GPL-3.0.txt` and `licenses\THIRD_PARTY_NOTICES.txt`; the program as distributed with the DLL is under the GPL v3's terms, the project's own code stays MIT. The installer has no licence to accept (the GPL asks for none): an information page before the installation (`InfoBeforeFile` per language, `tools/installer_notice.{en,ru}.txt`, UTF-8 with a BOM, else Inno reads them as ANSI) says which licences apply. `THIRD_PARTY_NOTICES.txt` holds the licence texts and copyright notices of the 139 crates compiled into the exe (normal dependencies for Windows from `cargo metadata`; of an `… OR MIT` choice the MIT file; a crate without a licence file gets its authors and the MIT or BSL text; identical texts once) and of egui's fonts (Ubuntu Font Licence, OFL, MIT); `tools/notices.py` writes it with Cargo.lock's FNV-1a hash, and `ui::licenses::tests` fails while the hash is old. The exe embeds `LICENSE`, `THIRD_PARTY_LICENSES.md`, the GPL and the notices (`include_str!`, `ui/licenses.rs`): About says the program goes with libmpv under the GPL v3 without warranty (its "Appropriate Legal Notices") and **Licenses…** shows the texts (a list of three parts, the lines with `ScrollArea::show_rows`, long ones wrapped at words to the text's width in monospace characters beforehand, `licenses::wrap`, as `show_rows` wants rows of one height).

- The version comes from `Cargo.toml` (`main::VERSION`); between releases the next version with `-dev`, and `build.rs` appends `git describe --tags --always`. Release: drop `-dev`, commit `Version X.Y.Z`, tag `vX.Y.Z`, then set the next `-dev` version.
- The release profile has `panic = "abort"` and no console: a panic shows a message box (`main::install_panic_hook`).
- Commits in this repository end with a trailer naming the Claude model that did the work, e.g. `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>` (this overrides the global "no Co-Authored-By" rule for this repo only). Commit only when the user asks.
- GUI checks: the OpenGL client area cannot be captured with `PrintWindow` on an NVIDIA machine, so the user checks the picture; logs (`METALMPV_TRACE`) show what mpv does. A launched window takes the focus: warn the user before launching test windows and before any simulated input, and close test windows with `taskkill /PID` (WM_CLOSE, which saves the settings).
