# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MetalMPV is a Windows-only video player written in Rust with egui/eframe 0.36 (glow); playback is libmpv's (`libmpv-2.dll`, loaded at run time). The layout is a classic player's: a frameless window with its own title row, the picture, a control bar under it (seek bar across the width; time on the left, the buttons in the middle with a round Play in their centre, volume and fullscreen on the right), an optional playlist on the right, a yellow OSD line in the top left corner after seeks. Priorities: opening a file fast, instant keyframe seeking, responsiveness, few settings. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone, no imperatives).

The name is written `MetalMPV` wherever people read it (UI, window title, READMEs, installer, `%APPDATA%\MetalMPV`, `%LOCALAPPDATA%\Programs\MetalMPV`, `MetalMPV_<ver>_Setup.exe`) and `metalmpv` wherever it is an identifier (Cargo package, `metalmpv.exe`, the GitHub repo `Fan4Metal/metalmpv`, the single-instance names).

## Commands

```
python tools/get_libmpv.py       # fetches the pinned libmpv-2.dll into vendor\libmpv (build.py and make_release.py do it)
uv run build.py                  # closes a metalmpv.exe running from target\, fetches libmpv if missing, cargo build --release
cargo build --release            # target\release\metalmpv.exe; build.rs copies libmpv-2.dll next to it
cargo test                       # unit tests (no DLL needed)
cargo test sys -- --ignored      # loads vendor\libmpv\libmpv-2.dll for real
cargo clippy --all-targets       # must stay warning-free
cargo fmt                        # default rustfmt (width 100)
python tools/make_release.py     # libmpv, tests, release build, dist\MetalMPV_<ver>_Setup.exe (Inno Setup 6) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy
python tools/icon_png.py         # images\icon.png from the exe's icon
python tools/notices.py          # licenses\THIRD_PARTY_NOTICES.txt after the dependencies change (a test fails until then)
METALMPV_TRACE=1                 # debug log with millisecond timings (start → window → file loaded → first frame), mpv's info messages
METALMPV_TRACE=2                 # also mpv's verbose messages
METALMPV_HWDEC=nvdec             # force mpv's hwdec option (measurements)
METALMPV_MPV="name=value;…"      # extra mpv options (measurements, diagnostics)
```

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files; the tag must equal the version in `Cargo.toml`. Creating or pushing a tag publishes a public release, so do it only when the user asks. `tools/setup.iss` installs per user. `.cargo/config.toml` links the CRT statically. These scripts mirror those of disk_flashlight, qview, qrec and metalmd; keep them in step (the libmpv steps are this project's own).

Trying a change: `cargo test` and `cargo clippy --all-targets`, then `uv run build.py` and run `target\release\metalmpv.exe <file>`; when the change concerns the installed copy (installer, portable mode, the DLL) or the user runs the program all day, `python tools/make_release.py --no-tests --install`. A test run with logs: start the exe with `METALMPV_TRACE=1` and stdout/stderr redirected to a file (the release exe has no console, but inherited handles work), close it with `taskkill /PID` (no `/F`).

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `metalmpv.exe` locks the release binary; `build.py` closes it first. Heredocs containing Rust code break the Bash tool (lifetime apostrophes), and backslashes in Python code passed through it get eaten; write files with the Write/Edit tools.

## Architecture

- **`main.rs`**: arguments (`--export-icon`, `--register`/`--unregister` (the file types, for the installer; named in the language of Windows), `--version`, `--help`, otherwise files; `normalize` fixes Explorer's `C:"`), `instance::forward` (a running copy takes the files), the panic hook, logging (`METALMPV_TRACE`), the **mpv start on a thread of its own** (`player::boot`: loading the DLL and `mpv_initialize`, ~15 ms) while eframe makes the window, `NativeOptions` (glow, `with_decorations(false)`, resizable, drag and drop, `window_builder` turning a saved fullscreen into maximized and a saved maximized into `MAXIMIZE_WHEN_SHOWN`).
- **`mpv/sys.rs`**: the libmpv C API declared by hand (client.h 2.5, render.h, render_gl.h): `LoadLibraryExW` of `libmpv-2.dll` next to the exe (a debug build also tries `vendor\libmpv`), `GetProcAddress` per function into `struct Api` (a macro), client API major version checked. The exe has no import of the DLL: without it the program starts and says what is missing. Struct layouts are tested (x64 sizes).
- **`mpv/mod.rs`**: the safe layer: `Mpv` (create with options, `command`/`set`/`get`/`observe`, all **asynchronous**, `next_event` with `mpv_wait_event(0)`, owned `Event`s) and `RenderContext`. render.h's threading rules: the render API is used on the UI thread, so the UI thread never calls anything that waits for the core; the synchronous `mpv_command`/`mpv_get_property`/`mpv_set_property` are deliberately not wrapped. The wakeup and update callbacks only call `ctx.request_repaint()`; since mpv may call them from inside a libmpv call, the app never calls mpv inside `ctx.input/memory/data` closures (egui's lock).
- **`player.rs`**: `Player`: mpv's options (`vo=libmpv`, `hwdec=auto-safe`, `keep-open=yes`, `video-timing-offset=0` so rendering never waits for a frame's display time, `audio-display=no`, mpv's own UI, bindings, scripts and config off), observed properties into `State`, `poll` → `Happened` (file loaded, end of file, failure, seek done), commands with the seek mode always explicit (`relative+keyframes`, `relative+exact`, `absolute+…`, `frame-step`/`frame-back-step`).
- **`video.rs`**: the picture. The render context is made in `App::new` (eframe's GL context is current there) before the first `loadfile` (mpv's video output fails without it). mpv renders into an FBO with an RGBA8 texture of the video area's pixel size, inside an egui paint callback (`egui_glow::CallbackFn`), without `FLIP_Y` (mpv puts the top row first into an FBO, where egui expects it; the flag is for the default framebuffer); the texture is shown with `painter.image`. A size change re-specifies the storage of the same texture name (eframe cannot free a texture registered with `register_native_glow_texture`, a new one per size would leak). A new frame is rendered only when `mpv_render_context_update` says so or the size changed. The callback runs for every frame a file is loaded, **before the video's size is known**: mpv publishes the size only after its first frame was rendered and otherwise waits 200 ms for it ("mpv_render_context_render() not being called or stuck"). `get_proc_address`: `wglGetProcAddress`, then opengl32.dll's exports.
- **`playlist.rs`**: the playlist is the app's (one `loadfile … replace` at a time; `eof-reached` moves on): natural sort, folder contents (`MEDIA_EXTENSIONS`), M3U/M3U8 files (`PLAYLIST_EXTENSIONS`) replaced by their entries in `App::open`/`add` (`expand_lists`, `m3u_entries`: comments skipped, relative paths from the list's folder, addresses kept; a list does not fill the folder; an `#EXTINF` line describes the next entry as a `Channel`: the title after the first comma outside quotes, `tvg-logo`, `group-title`, control characters dropped; kept in `Playlist::channels` by path (`describe`, `channel`, `title`: the channel's name, else the file name; used by the list, the window title, Sort and saved frames) and written back by `m3u_text`). **`logos.rs`**: the channels' logos for the playlist's visible rows (`Logos::get`, `channel_logos`): only `https://` on port 443 and no local host or private IPv4 (`allowed`), WinHTTP (`win::https_get`, no HTTPS-to-HTTP redirect), 512 KB, PNG/JPEG of at most 2048 px decoded with `image::Limits`, a 64 px texture; cached 30 days in `logos\<FNV-1a of the URL>` next to the settings; four threads started with the first logo; `cargo test logo_of_a_site -- --ignored` goes to the network, current/selected entries that follow their files through removal and sorting.
- **`app.rs`**: the eframe `App`. Every action of keys, buttons and menus is an `input::Cmd`, gathered during the frame and run at its end (`App::run`). `logic` (also while minimised) takes other starts' files (`instance::take`; files arriving within 1.5 s make one playlist, as Explorer starts one process per selected file) and the player's events (end of file → next entry; a failed file is skipped). `ui`: dropped files, keys (focus surrendered first, nothing while a modal is open), resize strips, title row, control bar, playlist, the picture or a placeholder (the start screen as in qview — icon, name, version, hint — while idle, with the recent files under RECENT as in metalmd (`settings.recent`, `recent_files`, ten paths, the latest first, added on `FileLoaded` for files on disk while `remember_recent` is on; the whole page centred a little above the middle, each line centred under the hint; as many rows as the height allows, at most eight, the name and folder of each a clickable area over the video area's drag area; **Clear the list**; Forget in the settings clears them too, as does turning `remember_recent` off); an audio file's cover with its title, artist and album (`audio_cover`), else its title; the error), OSD (under the fullscreen title strip while that is shown), fullscreen panels (the control bar at the bottom and a strip with the file's name at the top that takes no clicks, `fullscreen_title`, both of `BAR_BG` with the `fullscreen_transparency`; each shown on its own while the pointer is near its edge, the bar also while a seek is dragged or the tracks window is open: `fullscreen_panels`; the pointer hides after 0.5 s of rest away from them unless the information window is open), Settings and About. The window is maximized while cloaked when it was saved maximized (`win::show_maximized`, qview's way). `on_exit` frees the render context before the core. The picture's context menu works as Windows' menus do (`video_area`): it opens when the right button pressed on the picture is let go and closes on any press off the menus, however far the pointer went meanwhile (egui's click allows 6 points, so clicks with the mouse on the move were lost). `keep_awake` (in `logic`): mpv inhibits sleep only for its own video window, so the app calls `win::keep_awake` (`SetThreadExecutionState`, `ES_CONTINUOUS`) when it changes: display and system while a picture plays in sight, system for sound or a minimised window, nothing when paused, at the end or idle.
- **`frameless.rs`**: the window has no Windows frame but is resizable for Windows (`WS_SIZEBOX`/`WS_MAXIMIZEBOX`: Aero Snap, Win+arrows, maximizing to the work area, which winit's `WM_NCCALCSIZE` limits to `rcWork`). No window region (qrec's way loses the DWM shadow): `win::round_corners` asks DWM for rounded corners (Windows 11; square on Windows 10). Strips along the edges start `ViewportCommand::BeginResize`. The title row, the picture and the control bar's free space move the window (`frameless::drag_area`, `StartDrag`; not in fullscreen); those areas leave the 5-point edge strips alone, since a widget registered later covers an earlier one. Fullscreen turns winit's undecorated shadow off (`WindowExtWindows::set_undecorated_shadow`, the only use of the `winit` dependency), else winit moves the client area a pixel down and the bottom row falls off the screen. The pointer is hidden with `CursorIcon::None` (egui-winit shows it again on any icon change after `CursorVisible(false)`).
- **`instance.rs`**: one window per exe (qview's): a mutex `Local\metalmpv.<hash of the exe path>` and a message-only window that takes paths by `WM_COPYDATA`; `ChangeWindowMessageFilterEx` lets an elevated copy take them.
- **`input.rs`**: `Cmd` and the key map (`command`, tested): Space, Left/Right (short step on keyframes), Ctrl (long step), Shift (1 s exact), `,`/`.` and `D`/`F` (frames), Up/Down and the wheel (volume), `M`, Home/End, PgUp/PgDn, Enter/F11/double click (fullscreen), middle click on the picture (playlist, like `L`), Esc (`Cmd::Escape`: the information window, else fullscreen, else the program closes), Ctrl+O, `L`, F1, F5 / Ctrl+`,`, Delete, `I` (file information), `U` and `F7` (`Cmd::ToggleVideoPanel`: the Video, sound and subtitles panel; `U` next to `I`, `F7` as in GOM Player), `O` (the position, the duration and the chapter on the OSD, `Osd::Position`, as mpv's `o`), `1`–`4` (`Cmd::WindowScale`: the window for 50 %/100 %/150 %/200 % of the video), `5` (`Cmd::FitScreen`: the largest window without black bars), `` ` ``/`Ё` (`Cmd::FitWindow`: the window to the picture shown), `Ctrl+U` (`Cmd::OpenUrl`, `ui/url.rs`: a modal with a field; `playlist::is_url` — a scheme before `://` — keeps an address out of `normalize`'s `absolute`, the cover search, Show in folder and the info's Folder row, which becomes Address; `ytdl=no`, so only direct links and streams), `Shift+.`/`Shift+,`/`Shift+0` (`Cmd::SubDelay`, mpv's `sub-delay` by 100 ms; egui has no `<`/`>` keys and passes the physical ones with Shift), `C`/`X`/`Z` (`Cmd::Speed`: the steps of `format::SPEEDS`, 0.25× to 4×, as in GOM; also the context menu's **Speed** submenu, `Cmd::SetSpeed`; mpv's `speed` with its pitch correction, kept between files, not saved), `6` (`Cmd::ToggleFill`: fullscreen with mpv's `panscan` 1, the picture cropped to fill the screen; `6` again puts `panscan` back to 0 and stays in fullscreen, leaving fullscreen does so too), all also in the context menu's **Zoom** submenu. Held keys repeat only seeks, frame steps and the volume.
- **`tracks.rs`**: the file's tracks from mpv's `track-list` (observed as `MPV_FORMAT_NODE`; `mpv/mod.rs` copies nodes into `Value::List`/`Value::Map`), their names in both languages (`name_in`: the language first, the title after a dash unless it names the language itself) and badges (`badges_in`: codec, channels, external/forced/default), cycling (`A` round the audio tracks, `S` and `J` through the subtitles and then none; Stop has no key, `V` off and back), `SUBTITLE_EXTENSIONS` (a subtitle file dropped on a playing video is added with `sub-add … select` instead of replacing the playlist). `cargo test track_list -- --ignored` plays a sample headless (`vo=null`, `ao=null`) and reads its tracks.
- **`resume.rs`**: where files were left and which tracks they played (`Positions`, `Left`, `Tracks`, tested): the position kept for files of 5 min or more between 10 s after the start and 30 s before the end; the audio and subtitle ids (`remember_tracks`) whatever the position, for files with more than one audio track or with subtitles; 200 at most, paths without regard to case. The app remembers the file playing before another is loaded, on Stop and in `save` (every 30 s and on exit), from mpv's `path`/`time-pos`/`duration`; `Player::load(path, start, tracks)` resumes with `loadfile … replace -1 start=…,aid=…,sid=…` (a file-local option; the index before the options since mpv 0.38) and the OSD says so. A file without tracks of its own to come back to gets, once loaded (`App::pick_like_tracks`, `prefer_last_tracks`), the audio and subtitles most like those last chosen by hand (`App::select_track` records them): `tracks::most_like` scores the same title 2 and the same language 1 (codes compared by their English names), nothing alike leaves mpv's choice; meant for series. mpv's watch-later files are not used: they bring back the volume too, and must be written by a command before every change of file.
- **`chapters.rs`**: the file's chapters from mpv's `chapter-list` (observed as a node, sorted by start; a title that only numbers the chapter, "Chapter 01", is dropped and the interface numbers it), `current` (the last started, 50 ms of slack). Shown as gaps in the seek bar (`chapter_marks`, toggled in the context menu's **Chapters** submenu and in the settings), the chapter's name in the seek bar's tooltip, a folding section under the playlist (its open state in egui memory) and the submenu; `Cmd::Chapter` seeks exactly (a keyframe seek lands in the chapter before) and shows the OSD's chapter line. `cargo test chapter_list -- --ignored` with METALMPV_SAMPLE reads a file's chapters headless.
- **`fonts.rs`**: the system's font families for the subtitle and OSD settings (fontdb, listed on a thread of its own the first time the settings page asks, never at start-up; each family's face nearest to an upright regular), `read` (a face for egui, checked with skrifa first: egui panics on a font it cannot parse). The subtitles take a family by name (`sub-font`, mpv/libass finds it; `sub-scale` for the size of all subtitles); the OSD is egui's, so its family's file and face number are kept in the settings and read at start-up (`style::set_fonts`, the family `style::osd_family`, backed by the interface's fonts).
- **`cover.rs`**: a file's cover, found on a thread of its own once the file is loaded (`load`, a receiver; `App::update_cover` makes the texture with mipmaps and drops the pixels): the front cover of its tags through lofty (audio formats; `read_properties(false)`), MP4's `moov/udta/meta/ilst/covr` read by hand (lofty 0.25 skips a box with a 64-bit size 8 bytes too far, so a film over 4 GB with its `mdat` before the `moov` had no cover), an image attachment of a Matroska file read by hand (EBML: the Segment's SeekHead says where the Attachments are, else its children are walked up to the first Cluster; `cover.` before `cover_land.`, `small_cover.`), or for an audio file `cover`/`folder`/`front`… next to it (mpv's `cover-art-auto` names). JPEG and PNG, decoded with `image` and scaled to 2048 px at most; the stored bytes are kept for **Save the cover…**. mpv shows covers only in place of the video (`audio-display=no` here), hence all this. `cargo test cover_of_sample -- --ignored --nocapture` with METALMPV_SAMPLE.
- **`info.rs`**: what the information window says, `_in(lang, …)` and tested: the tags (`tags_in`: known ones first, in order, named in both languages, then the rest as the file names them; `tag` case-insensitive), size, bitrate, container (`container` from FFmpeg's demuxer name), chapters, each track's main details in one line (`track_details_in`) and its rows (`track_rows_in`: format, `codec-profile`, Dolby Vision, size, aspect, fps, rotation, channels and layout, kHz, bitrate, bits per pixel·frame and the stream's size estimated from it, flags, the track's own tags; for the video on screen also bit depth and chroma subsampling from the pixel format (`sampling`), scan, color range, primaries, transfer, matrix, HDR light levels and the decoder, hardware or software) and `report_in`, all of it for the clipboard. The state behind it: mpv's `metadata`, `file-size`, `file-format`, `video-params` (observed; they change only on load), the tracks' `demux-*` fields and `metadata`, and the scan from `video-frame-info`, asked for (`Player::ask_scan`, not observed: it changes every frame) while the window is open. mpv's own Matroska demuxer gives no per-track bitrate or tags; level, CABAC, reference frames and bitrate mode are not in mpv at all (MediaInfo would be needed).
- **`format.rs`**: times (`MM:SS`, `H:MM:SS`), percentages (decimal comma in Russian), seek steps and the OSD lines (`Osd`) in both languages, tested with `_in(lang, …)`.
- **`ui/`**: `style.rs` (the palette; always dark), `icons.rs` (media icons drawn with lines: the default fonts have no such symbols), `controls.rs` (the control bar; flat buttons with `Sense::CLICK`, not focusable; Upside down is `hflip` plus half a turn (`Adjust::rotation` into `video-rotate`), both flips half a turn alone: FFmpeg's `vflip` accepts CUDA frames and flips them by a negative stride, which the CUDA interop refuses (`cuMemcpy2DAsync … CUDA_ERROR_INVALID_VALUE`, a blue picture). `picture_adjustments` runs with `hwdec=auto-safe` to catch this. Not saved; they last over every file. **Save the frame** (`Cmd::SaveFrame`, `Ctrl+E`): `screenshot-to-file <path> video` into `win::pictures_dir()`\MetalMPV (`SHGetKnownFolderPath`), `<stem> <H-MM-SS>.png`, never over another. `cargo test picture_adjustments -- --ignored --nocapture` runs them on a real file headless.
- **`taskbar.rs`**: the taskbar button through `ITaskbarList3`, declared by hand (a vtable of the methods in order; `windows-sys` has no COM interfaces; COM is already up on the UI thread from winit's `OleInitialize`): the position as progress per mille (`TBPF_PAUSED` yellow when paused, none when idle) and three thumbnail buttons (Previous, Play/Pause, Next; disabled when there is no previous or next), whose icons are drawn here (`glyph_pixels`, 4×4 samples, the small icon size at the window's DPI) into `CreateIconIndirect`. Nothing is called before `TaskbarButtonCreated` (a registered message `win::hook_window` turns into `Hooked::TaskbarButton`; Explorer sends it again after a restart); clicks come as `WM_COMMAND`/`THBN_CLICKED`, `Hooked::Thumb(id)`. `App::show_on_taskbar` (in `logic`) passes what changed.
- **`sizing.rs`**: the window for the picture (`1`–`5`, `` ` ``; tested), in pixels: `fitted` (the picture shown whole in an area), `client_size` (the picture plus the chrome — title row, control bar, playlist — scaled down to the work area keeping its shape, not under `MIN_SIZE`), `placed` (centred where the window was, moved onto the work area). `App::size_window` measures the chrome as the window minus the video area of the last windowed frame, restores a maximized window and calls `win::set_rect`; in fullscreen it leaves it and sizes the window in the next frame (`pending_picture`).
- **`audio.rs`**: the sound's settings (tested): `Channels` (stored names, mpv's `audio-channels`: `auto-safe` for Auto), `BOOSTS` and `boost_label` (`volume-max`), `NORMALIZE_FILTER` (`af`, `lavfi=[dynaudnorm=…]`), `Passthrough` (`audio-spdif`: off, S/PDIF `ac3,dts`, HDMI also `eac3,dts-hd,truehd`; WASAPI passes it through in exclusive mode only, which mpv asks for itself, and a format the device refuses is decoded), `DELAY_STEP` (`audio-delay`, `Ctrl+=`/`Ctrl+-`/`Ctrl+0`, not kept), `devices_from_value` (`audio-device-list`, observed, WASAPI devices only: another driver's entry would switch the driver), `device_to_use`: mpv does not fall back from a forced device that is gone (ao.c's `forced_dev`, no sound), so `App::follow_audio_device` (in `logic`) gives mpv the chosen device only while it is listed, else `auto`, and follows devices coming and going. `Player::new` takes an `audio::Setup` and sets channels, filter, ceiling, volume and mute before the first `loadfile`. The control bar's volume reaches `volume_max`, with a tick at 100 %. `cargo test audio_settings -- --ignored --nocapture` checks them on a real file headless.

Measured (release, RTX 4070 Ti SUPER, 1080p60 HEVC mp4, warm start): window at ~150 ms after process start, render context ~80 ms (almost all of it the CUDA interop; without it `d3d11va-copy` decodes and the first frame comes later), `loadfile` at ~240 ms, file loaded at ~250 ms, first video frame rendered at ~380–470 ms. Before the render callback ran ahead of the video size, the first frame came 200 ms later.

## libmpv

`tools/get_libmpv.py` (stdlib only) downloads the pinned `mpv-dev-x86_64-20261012-git-88eb9f2e73.7z` of shinchiro/mpv-winbuild-cmake and 7-Zip's `7zr.exe` 26.03 (py7zr and Windows' tar cannot unpack the archive's BCJ2 filter), both checked by SHA-256, into `vendor\` (git-ignored, cached in CI by the script's hash). Updating libmpv: change the constants there (asset name, URL, SHA-256 from the GitHub API's `digest`) and the version in `THIRD_PARTY_LICENSES.md`. The DLL is ~115 MB unpacked. **The build is GPLv3** (mpv's `gpl` feature, FFmpeg `--enable-gpl --enable-version3`): the installer and the zip ship `THIRD_PARTY_LICENSES.md` with the source links, `licenses\GPL-3.0.txt` and `licenses\THIRD_PARTY_NOTICES.txt`; the program as distributed with the DLL is under the GPL v3's terms, the project's own code stays MIT. The installer has no licence to accept (the GPL asks for none): an information page before the installation (`InfoBeforeFile` per language, `tools/installer_notice.{en,ru}.txt`, UTF-8 with a BOM, else Inno reads them as ANSI) says which licences apply. `THIRD_PARTY_NOTICES.txt` holds the licence texts and copyright notices of the 148 crates compiled into the exe (normal dependencies for Windows from `cargo metadata`; of an `… OR MIT` choice the MIT file; a crate without a licence file gets its authors and the MIT or BSL text; identical texts once) and of egui's fonts (Ubuntu Font Licence, OFL, MIT); `tools/notices.py` writes it with Cargo.lock's FNV-1a hash, and `ui::licenses::tests` fails while the hash is old. The exe embeds `LICENSE`, `THIRD_PARTY_LICENSES.md`, the GPL and the notices (`include_str!`, `ui/licenses.rs`): About says the program goes with libmpv under the GPL v3 without warranty (its "Appropriate Legal Notices") and **Licenses…** shows the texts (a list of three parts, the lines with `ScrollArea::show_rows`, long ones wrapped at words to the text's width in monospace characters beforehand, `licenses::wrap`, as `show_rows` wants rows of one height).
