# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

MetalMPV is a Windows-only video player written in Rust with egui/eframe 0.36 (glow); playback is libmpv's (`libmpv-2.dll`, loaded at run time). The layout is a classic player's: a frameless window with its own title row, the picture, a control bar under it (seek bar across the width; time on the left, the buttons in the middle with a round Play in their centre, volume and fullscreen on the right), an optional playlist on the right, a yellow OSD line in the top left corner after seeks. Priorities: opening a file fast, instant keyframe seeking, responsiveness, few settings. `README.md` / `README.ru.md` are the user-facing docs and must be kept in sync (both languages, cross-linked, formal tone, no imperatives).

The name is written `MetalMPV` wherever people read it (UI, window title, READMEs, installer, `%APPDATA%\MetalMPV`, `%LOCALAPPDATA%\Programs\MetalMPV`, `MetalMPV_<ver>_Setup.exe`) and `metalmpv` wherever it is an identifier (Cargo package, `metalmpv.exe`, the GitHub repo `Fan4Metal/metalmpv`, the single-instance names).

## Commands

```
python tools/get_libmpv.py       # fetches the pinned libmpv-2.dll into vendor\libmpv (build.py and make_release.py do it)
uv run build.py                  # closes a metalmpv.exe running from target\, fetches libmpv if missing, cargo build --release
cargo build --release            # target\release\metalmpv.exe; build.rs copies libmpv-2.dll next to it
cargo test                       # unit tests (no DLL needed)
cargo test sys -- --ignored      # loads vendor\libmpv\libmpv-2.dll for real
cargo clippy --all-targets       # must stay warning-free
cargo fmt                        # default rustfmt (width 100)
python tools/make_release.py     # libmpv, tests, release build, dist\MetalMPV_<ver>_Setup.exe (Inno Setup 6) and _portable.zip
python tools/make_release.py --no-tests --install   # the same, then installs it silently over the installed copy
python tools/icon_png.py         # images\icon.png from the exe's icon
python tools/notices.py          # licenses\THIRD_PARTY_NOTICES.txt after the dependencies change (a test fails until then)
METALMPV_TRACE=1                 # debug log with millisecond timings (start → window → file loaded → first frame), mpv's info messages
METALMPV_TRACE=2                 # also mpv's verbose messages
METALMPV_HWDEC=nvdec             # force mpv's hwdec option (measurements)
METALMPV_MPV="name=value;…"      # extra mpv options (measurements, diagnostics)
```

Releases: pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`, which runs `make_release.py` and publishes both files; the tag must equal the version in `Cargo.toml`. Creating or pushing a tag publishes a public release, so do it only when the user asks. `tools/setup.iss` installs per user. `.cargo/config.toml` links the CRT statically. These scripts mirror those of disk_flashlight, qview, qrec and metalmd; keep them in step (the libmpv steps are this project's own).

Trying a change: `cargo test` and `cargo clippy --all-targets`, then `uv run build.py` and run `target\release\metalmpv.exe <file>`; when the change concerns the installed copy (installer, portable mode, the DLL) or the user runs the program all day, `python tools/make_release.py --no-tests --install`. A test run with logs: start the exe with `METALMPV_TRACE=1` and stdout/stderr redirected to a file (the release exe has no console, but inherited handles work), close it with `taskkill /PID` (no `/F`).

Toolchain: stable MSVC Rust plus VS 2022 Build Tools. In the Bash tool, `cargo` is not on PATH; prefix commands with `export PATH="$HOME/.cargo/bin:$PATH"`. A running `metalmpv.exe` locks the release binary; `build.py` closes it first. Heredocs containing Rust code break the Bash tool (lifetime apostrophes), and backslashes in Python code passed through it get eaten; write files with the Write/Edit tools.

## Architecture

- **`main.rs`**: arguments (`--export-icon`, `--register`/`--unregister` (the file types, for the installer; named in the language of Windows), `--version`, `--help`, otherwise files; `normalize` fixes Explorer's `C:"`), `instance::forward` (a running copy takes the files), the panic hook, logging (`METALMPV_TRACE`), the **mpv start on a thread of its own** (`player::boot`: loading the DLL and `mpv_initialize`, ~15 ms) while eframe makes the window, `NativeOptions` (glow, `with_decorations(false)`, resizable, drag and drop, `window_builder` turning a saved fullscreen into maximized and a saved maximized into `MAXIMIZE_WHEN_SHOWN`).
- **`mpv/sys.rs`**: the libmpv C API declared by hand (client.h 2.5, render.h, render_gl.h): `LoadLibraryExW` of `libmpv-2.dll` next to the exe (a debug build also tries `vendor\libmpv`), `GetProcAddress` per function into `struct Api` (a macro), client API 2.3 or a later 2.x required (`API_MINOR`: mpv 0.38's `loadfile` with an index). The exe has no import of the DLL: without it the program starts and says what is missing (`sys::LoadError` into `player::EngineError`: `NoDll`, `BadDll`, `Failed`; `message()` is the window's text, wrapped under the icon, short for a missing or unusable DLL — the paths and Windows' error are the log's; the window title is the app's name while there is no engine). Struct layouts are tested (x64 sizes).
- **`mpv/mod.rs`**: the safe layer: `Mpv` (create with options, `command`/`set`/`get`/`observe`, all **asynchronous**, `next_event` with `mpv_wait_event(0)`, owned `Event`s) and `RenderContext`. render.h's threading rules: the render API is used on the UI thread, so the UI thread never calls anything that waits for the core; the synchronous `mpv_command`/`mpv_get_property`/`mpv_set_property` are deliberately not wrapped. The wakeup and update callbacks only call `ctx.request_repaint()`; since mpv may call them from inside a libmpv call, the app never calls mpv inside `ctx.input/memory/data` closures (egui's lock).
- **`player.rs`**: `Player`: mpv's options (`vo=libmpv`, `hwdec=auto-safe`, `keep-open=yes`, `video-timing-offset=0` so rendering never waits for a frame's display time, `audio-display=no`, mpv's own UI, bindings, scripts and config off), observed properties into `State`, `poll` → `Happened` (file loaded, end of file, failure, seek done, `Expanded`: a list mpv opened itself, an M3U at an address or inside a list, reported by `END_FILE` with `REDIRECT`; its entries from mpv's `playlist` replace the entry in the app's playlist (`Playlist::expand_current`) and `playlist-clear` leaves mpv only the one it plays); a `loading` flag from `load` to `FileLoaded`/failure ignores the end of the file before (Next in its last second skipped the file chosen), `starts_due` (loads whose `START_FILE` has not come) an error ending the file before, and `stopped` (after `stop`, until a load) a late end; a `loadfile` refused (reply id `LOAD`) is a failure, an end of the file more than 15 s before the duration is `Happened::NoData` (`data_end`: the data ends early, a download not finished; within 3 s of a forward seek its target counts, as an MP4 then gives the duration as the position; otherwise the position; Matroska and MP4 have durations that are not estimates, other formats count only where the file shows the lack, `incomplete.rs`: `unfilled`, 64 KB of zeros at the target's share of the size (or halfway to the duration after playing), the room a torrent keeps, or `truncated`, fewer bytes than the header declares (an MP3's Xing/VBRI bytes, else its first frame's bitrate over mpv's duration, from the ID3 length, a frame counted only with the next header at its length; only for mpv's `file-format` `mp3`, as AAC's and AC3's data hold MP3 frame headers by chance; a WAV's RIFF size); a whole MP3 whose duration was over-estimated from its first frame's bitrate has neither; `cargo test an_mp3_download -- --ignored` plays three cut copies), and the app leaves mpv paused there (`stay_in_incomplete`), Play going on from where there was data (`data_end_at`), or moves on as at an end; commands with the seek mode always explicit (`relative+keyframes`, `relative+exact`, `absolute+…`, `frame-step`/`frame-back-step`).
- **`video.rs`**: the picture. The render context is made in `App::new` (eframe's GL context is current there) before the first `loadfile` (mpv's video output fails without it). mpv renders into an FBO with an RGBA8 texture of the video area's pixel size, inside an egui paint callback (`egui_glow::CallbackFn`), without `FLIP_Y` (mpv puts the top row first into an FBO, where egui expects it; the flag is for the default framebuffer); the texture is shown with `painter.image`. A size change re-specifies the storage of the same texture name (eframe cannot free a texture registered with `register_native_glow_texture`, a new one per size would leak). A new frame is rendered only when `mpv_render_context_update` says so or the size changed. While nothing is painted (minimised: eframe calls no `ui`; idle after Stop) `App::logic` calls `Video::skip_unseen` (`MPV_RENDER_PARAM_SKIP_RENDERING` and the swap report; eframe's GL context stays current on the UI thread), else mpv waited 200 ms per frame. `RenderContext` frees itself when dropped (an error path); replaced callbacks' boxes are kept. The swap is reported (`mpv_render_context_report_swap`) right after rendering: mpv makes no next frame before the report, and reporting it in the next paint took two paints a frame (240 fps video ran at 121 on a 239 Hz screen; at 60 Hz, 60 fps video could have run at 30). The callback runs for every frame a file is loaded, **before the video's size is known**: mpv publishes the size only after its first frame was rendered and otherwise waits 200 ms for it ("mpv_render_context_render() not being called or stuck"). `get_proc_address`: `wglGetProcAddress`, then opengl32.dll's exports.
- **`dock.rs`**, `App::playlist_window`: the playlist in a window of its own (`settings.playlist_detached`, `Cmd::TogglePlaylistWindow`: the playlist's last button, `icons::detach`, and the context menu). An immediate egui viewport as metalmd's detached tabs, frameless as the player's (`frameless::resize_edges`, its title row `ui::title::tool_row`: the name, close on the right, the rest drags it) (`show_viewport_immediate` in `ui`, the same `ui::playlist::panel` with `App` at hand; measured: a second immediate window does not lower the video's frame rate). The builder is made once per opening (a changed builder would move the window); eframe gives no handle, so the window is the visible one of the thread that is not the player's (`win::thread_windows`, again after `IsWindow` fails: the window may be made anew), put at `settings.playlist_rect` (its visible rectangle in pixels, DWM's extended frame bounds: `win::visible_rect`, `set_visible_rect`, kept each frame; else `dock::first_place`: the player's right edge, else its left, else over its right side, on the work area) and adopted (`win::adopt_playlist`: owned by the player through `GWLP_HWNDPARENT`, so above it, minimised with it, no taskbar button; rounded corners; subclassed). Its `WM_MOVING` draws it to the player's edges (`dock::snapped`, the rectangle the pointer alone gives, as the player's own magnet); at `WM_EXITSIZEMOVE` it is glued to the edge it touches (`dock::glue_of`), and the player's `WM_WINDOWPOSCHANGED` puts a glued one beside it (`dock::placed`; not while minimised, maximized or in fullscreen: `set_playlist_follow`). Not shown in fullscreen while it overlaps the player. Keys work in it (Esc closes it), dropped files go as on the player (`App::drop_files`: added to the playlist, opened when it is empty), media keys are hooked there too (`win::media_message`); its close button hides the playlist.
- **`playlist.rs`**: the playlist is the app's (one `loadfile … replace` at a time; `eof-reached` moves on): natural sort, folder contents (`MEDIA_EXTENSIONS`), M3U/M3U8 files (`PLAYLIST_EXTENSIONS`) replaced by their entries in `App::open`/`add` (`expand_lists`, `m3u_entries`: comments skipped, relative paths from the list's folder, `file:` addresses as paths (`file_uri_path`), `.` and `..` dropped (`lexical`), other addresses kept; an `.m3u` not in UTF-8 in the system's code page (`win::ansi_text`); an HLS list (`is_hls`) kept as a file mpv plays; a list does not fill the folder; an `#EXTINF` line describes the next entry as a `Channel`: the title after the first comma outside quotes, `tvg-logo`, `group-title`, control characters dropped; kept in `Playlist::channels` by path (`describe`, `channel`, `title`: the channel's name, else the file name; used by the list, the window title, Sort and saved frames) and written back by `m3u_text`). **`logos.rs`**: the channels' logos for the playlist's visible rows (`Logos::get`, `channel_logos`): only `https://` on port 443 and no local host or private IPv4 (`allowed`), WinHTTP (`win::https_get_once`: redirects followed by `fetch`, at most three, each checked by `allowed`; a host resolving to the local network or not resolving, one not of `[a-z0-9.-]`, a trailing dot and odd numeric hosts refused; the whole answer within twice the step's timeout), 512 KB, PNG/JPEG of at most 2048 px decoded with `image::Limits`, a 64 px texture; cached 30 days in `logos\<FNV-1a of the URL>` next to the settings (the URL on the first line, then the picture: a copy of another URL with the same hash is not taken; written as `.part` and renamed; a damaged copy fetched again; older ones deleted by a thread at the pool's start); at most `MAX_TEXTURES` kept, those shown longest ago dropped; four threads started with the first logo, the latest asked for first (`Wanted`, a `Condvar`), one waiting that was not asked for again within `STALE` (1 s) of the latest let go (its row scrolled away; asked anew when shown); `cargo test logo_of_a_site -- --ignored` goes to the network, the current entry follows its file through removal, sorting and moves; the selection is a set of paths (each entry is listed once: `select`, `toggle_selected`, `select_range` from `anchor`, `select_all`, `selection` in the list's order), so it follows its files too; `remove_many` selects the entry in the place of the first removed, `move_selected(slot)` moves the selection in its order (a slot counted before the move); `revision` counts the changes for views made of the list (`clear` keeps counting); the playing entry removed stays the current path (`gone`) and the entry after its place comes next (`after_gone`); the entry playing chosen again starts over; entries are deduplicated with a set (lists of thousands).
- **`app.rs`**: the eframe `App`. Every action of keys, buttons and menus is an `input::Cmd`, gathered during the frame and run at its end (`App::run`). `logic` (also while minimised) takes other starts' files (`instance::take`; files arriving within 300 ms of the last ones make one playlist, as Explorer starts one process per selected file, measured 6–20 ms apart; a double click on another file comes later and replaces it) and the player's events (end of file → next entry; a failed file is skipped). `ui`: dropped files, keys (focus surrendered first, nothing while a modal is open), resize strips, title row, control bar, playlist, the picture or a placeholder (the start screen as in qview — icon, name, version, hint — while idle, with the recent files under RECENT as in metalmd (`settings.recent`, `recent_files`, thirty paths (`settings::RECENT_COUNT`), the latest first, added on `FileLoaded` for files on disk while `remember_recent` is on; the whole page centred a little above the middle, each line centred under the hint; as many rows seen as the height allows, at most eight, the rest scrolling in their place (a `ScrollArea` in a child `Ui`; the wheel there scrolls instead of setting the volume, `recent_scroll`), the name and folder of each a clickable area over the video area's drag area; **Clear the list**; Forget in the settings clears them too, as does turning `remember_recent` off); an audio file's cover with its title, artist and album (`audio_cover`), else its title; the error), OSD (under the fullscreen title strip while that is shown), fullscreen panels (the control bar at the bottom and a strip with the file's name at the top that takes no clicks, `fullscreen_title`, both of `BAR_BG` with the `fullscreen_transparency`; each shown on its own while the pointer is near its edge, the bar also while a seek is dragged or the tracks window is open: `fullscreen_panels`; the pointer hides after 0.5 s of rest away from them unless the information window is open; `L` and the middle click show the playlist over the right side instead, `fullscreen_playlist`, `App::fullscreen_playlist_panel`: the screen's height, its width kept in egui memory apart from the window's and set by its left edge, the other panels narrowed to keep off it (`fullscreen_list_width`), `Esc` closes it before fullscreen, closed when fullscreen ends), Settings and About. The window is maximized while cloaked when it was saved maximized (`win::show_maximized`, qview's way). `on_exit` frees the render context before the core. The picture's context menu works as Windows' menus do (`video_area`): it opens when the right button pressed on the picture is let go and closes on any press off the menus, however far the pointer went meanwhile (egui's click allows 6 points, so clicks with the mouse on the move were lost); the middle button pressed on the picture shows or hides the playlist when let go, the same way (`middle_press`). `keep_awake` (in `logic`): mpv inhibits sleep only for its own video window, so the app calls `win::keep_awake` (`SetThreadExecutionState`, `ES_CONTINUOUS`) when it changes: display and system while a picture plays in sight, system for sound or a minimised window, nothing when paused, at the end or idle.
- **`frameless.rs`**: the window has no Windows frame but is resizable for Windows (`WS_SIZEBOX`/`WS_MAXIMIZEBOX`: Aero Snap, Win+arrows, maximizing to the work area, which winit's `WM_NCCALCSIZE` limits to `rcWork`). No window region (qrec's way loses the DWM shadow): `win::round_corners` asks DWM for rounded corners (Windows 11; square on Windows 10). Strips along the edges start `ViewportCommand::BeginResize`. The title row, the picture and the control bar's free space move the window (`frameless::drag_area`, `StartDrag`; not in fullscreen); those areas leave the 5-point edge strips alone, since a widget registered later covers an earlier one. Fullscreen turns winit's undecorated shadow off (`WindowExtWindows::set_undecorated_shadow`, the only use of the `winit` dependency), else winit moves the client area a pixel down and the bottom row falls off the screen. A window maximized before fullscreen stays `WS_MAXIMIZE` there and winit's `WM_NCCALCSIZE` gives it the work area (a black strip as tall as the taskbar, now and then): while `win::set_fullscreen` is on, the subclass answers `WM_NCCALCSIZE` itself with the window's rectangle within its monitor (`fullscreen_client`). The pointer is hidden with `CursorIcon::None` (egui-winit shows it again on any icon change after `CursorVisible(false)`).
- **`dialog.rs`**: the file dialogs (Open, Add, subtitles, Save the playlist, Save the cover, the frames' folder) each on a thread of its own (`Dialogs::start`, one at a time; the answer, `Ask` and the paths, taken in `logic` by `App::answer`): on the UI thread a dialog's own message loop held the frame and the picture stood still. The player's window is still the owner (`Owner`, its HWND as a `raw-window-handle`), so Windows disables it while the dialog is open and brings it back in front after; rfd initialises COM on the thread.
- **`instance.rs`**: one window per exe (qview's): a mutex `Local\metalmpv.<hash of the exe path>` and a message-only window that takes all of a start's paths in one `WM_COPYDATA` (NUL-separated); the files of the start itself count as the first of a batch (`App::last_received`); `ChangeWindowMessageFilterEx` lets an elevated copy take them.

## libmpv

`tools/get_libmpv.py` (stdlib only) downloads the pinned `mpv-dev-x86_64-20261012-git-88eb9f2e73.7z` of shinchiro/mpv-winbuild-cmake and 7-Zip's `7zr.exe` 26.03 (py7zr and Windows' tar cannot unpack the archive's BCJ2 filter), both checked by SHA-256, into `vendor\` (git-ignored, cached in CI by the script's hash). shinchiro keeps only the last 30 builds (about two months), so the archive is mirrored unchanged in a pre-release of this repository, `libmpv-<date>` (not a `v*` tag: no release workflow, not "latest"), tried first, the original as the fallback. Updating libmpv: mirror the new archive (`gh release create libmpv-<date> --prerelease --target main --notes-file … <archive>`, its hash checked first), change the constants there (asset name, both URLs, SHA-256 from the GitHub API's `digest`, the build's commit of mpv-winbuild-cmake — the tag's — and the FFmpeg commit the DLL names in `N-…-g<hash>`) and the same in `THIRD_PARTY_LICENSES.md` (the GPL's corresponding source). The DLL is ~115 MB unpacked. **The build is GPLv3** (mpv's `gpl` feature, FFmpeg `--enable-gpl --enable-version3`): the installer and the zip ship `THIRD_PARTY_LICENSES.md` with the source links, `licenses\GPL-3.0.txt` and `licenses\THIRD_PARTY_NOTICES.txt`; the program as distributed with the DLL is under the GPL v3's terms, the project's own code stays MIT. The installer has no licence to accept (the GPL asks for none): an information page before the installation (`InfoBeforeFile` per language, `tools/installer_notice.{en,ru}.txt`, UTF-8 with a BOM, else Inno reads them as ANSI) says which licences apply. `THIRD_PARTY_NOTICES.txt` holds the licence texts and copyright notices of the 139 crates compiled into the exe (normal dependencies for Windows from `cargo metadata`; of an `… OR MIT` choice the MIT file; a crate without a licence file gets its authors and the MIT or BSL text; identical texts once) and of egui's fonts (Ubuntu Font Licence, OFL, MIT); `tools/notices.py` writes it with Cargo.lock's FNV-1a hash, and `ui::licenses::tests` fails while the hash is old. The exe embeds `LICENSE`, `THIRD_PARTY_LICENSES.md`, the GPL and the notices (`include_str!`, `ui/licenses.rs`): About says the program goes with libmpv under the GPL v3 without warranty (its "Appropriate Legal Notices") and **Licenses…** shows the texts (a list of three parts, the lines with `ScrollArea::show_rows`, long ones wrapped at words to the text's width in monospace characters beforehand, `licenses::wrap`, as `show_rows` wants rows of one height).
